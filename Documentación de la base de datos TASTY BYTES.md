Tasty Bytes is one of the largest food truck networks in the world with localized menu options spread across 30 major cities in 15 countries. **Tasty Bytes is aiming to achieve 25% YoY sales growth over 5 years.**

As Tasty Bytes Data Scientists, we have been asked to support this goal by helping our food truck drivers more intelligently pick where to park for shifts. **We want to direct our trucks to locations that are expected to have the highest sales on a given shift. This will maximize our daily revenue across our fleet of trucks.**

To provide this insight, we will use historical shift sales at each location to build a model. This data has been made available to us in Snowflake.

Our model will provide the predicted sales at each location for the upcoming shift.

Tasty Bytes operates food trucks in cities across the globe with each truck having the ability to choose two different selling locations per day. The locations are mapped to SafeGraph points-of-interest. You want to join latitude and longitude from the SafeGraph Marketplace data to your shift sales data to use as features in model training.

*Note: The schemas "PUBLIC" and "INFORMATION_SCHEMA" are generated by default when creating any database in Snowflake. The PUBLIC schema is meant to be the default workspace. In this case, the functions and the stage for the data load from the S3 bucket is stored here. On the other hand, the INFORMATION_SCHEMA contains all the metadata of the database objects, like usage history logs, object types, etc.*

## Schema "RAW_POS"

### Table "country"
This table contains 30 rows

The columns that appear in this table are the following:
- **country_id**: Integer identificator for the country
- **country**: Name of the country (Ej.: "United States", "England", "Canada", etc.)
- **iso_currency**: ISO code for their currency using 3 letters (Ej.: "CAD", "USD", "EUR", etc.)
- **iso_country**: ISO code for their country using 2 letters (Ej.: "US", "GB", "CA", etc.)
- **city_id**: Integer identificator for the city 
- **city**: Name of the city (Ej.: "Manchester", "Toronto", "London", etc.)
- **city_population**: Population number of the city

*CHECAR DESPUÉS: This table containes a composite PK, made up of the columns: **country_id** and **city_id**.
OR...
This table containes a PK: **city_id**. Even though the table is named "country", it actually containes unique cities and some of them are from the same country.*
